# 1C2G 容量评估

2026-09-14 的隔离测试支持保留现有 Node.js 后端。没有证据表明运行内存需要通过语言迁移解决。当前应优先分流图片、音乐和字体下载，减少 AI 队列等待。

## 测试条件

每个生产结构容器限制 1 CPU、2 GiB 内存，禁用 swap，使用 Node 22 Alpine。PostgreSQL 位于容器外的本机隔离数据库。100 个测试宾客保持 100 条 SSE 连接，聊天每 800 ms 查询处理进度，活动与本人状态每 4 秒轮询。正式手机号、短信接口、真实 AI 均未用于此次压测。

模型替身每次延迟 750 ms，执行审查、判定、回应及回应检查的真实任务编排；它不评估模型正确率。单题场景包含开场及一次回答，完整场景包含开场及六次回答。所有任务经真实 HTTP、数据库事务、跨实例领取和服务端判定状态流转完成。

## 结果

| 场景 | 每实例任务名额 | 进程 RSS 峰值 | API P95 | 一轮答复 P95 | HTTP 失败 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 实例，同源资源，100 人各答 1 题 | 8 | 149.7 MiB | 501 ms | 49.0 s | 0 |
| 1 实例，独立静态服务，100 人各答 1 题 | 8 | 132.8 MiB | 390 ms | 49.4 s | 0 |
| 1 实例，独立静态服务，100 人各答 1 题 | 32 | 134.6 MiB | 1184 ms | 13.7 s | 0 |
| 2 实例，独立静态服务，100 人各答 6 题 | 32 | 135.9 / 134.3 MiB | 638 ms | 7.3 s | 0 |

完整场景运行约 46 秒，处理 600 份答卷、2600 次替身模型请求和 7369 次业务 HTTP 请求。两个实例的进程平均 CPU 占单核约 48% / 47%，该均值包含测试后的恢复观察期；不表示瞬时 CPU 无峰值。停止请求 10 秒后的 RSS 为 98.2 / 97.2 MiB。所有测试容器的 OOM 和 OOM kill 计数均为 0。

RSS 包含进程映射的共享页。cgroup 内存按内核的页归属计费，两项数值不可相加。原始记录保留 RSS、堆、外部缓冲、cgroup 内存、CPU 节流、事件循环延迟和恢复期数据。

固定冷启动资源清单中，100 位访客下载约 1.522 GB 静态文件。分流后应用返回的页面和资源字节从约 1.537 GB 降至 15.26 MB，降幅约 99%。这组字节数不包含 API、SSE、TLS 和传输压缩差异，也未下载所有字体分片。它说明资源归属变化，不是月流量账单预测。该次构建的完整静态包约 28 MiB，宾客不会同时下载全部主题文件。

这组历史数据包含编译后 JS/CSS 的外部托管。当前方案仅托管 `public`，应用 JS/CSS 由网站提供，历史字节数不能代表当前方案的流量。压测脚本已采用当前资源边界，新报告写入 `.temp/reports/capacity-*/`；此次资源调整未重跑容器压测。

同源基线的状态轮询同时开始；后续测试将周期轮询起点错开到 4 秒内。三次前期分流尝试遇到 Windows 压测入口连接拒绝，未作为通过样本。测试入口增大监听队列后，分流、32 名额及双实例完整场景通过。不能把同源与分流场景全部耗时差异归因于资源服务；8 与 32 名额的分流测试使用相同轮询方式。

原始结果：[同源基线](capacity-1-local.json)、[独立静态服务](capacity-1-static.json)、[32 任务名额](capacity-1-static-workers32.json)、[双实例六题流程](capacity-2-static-full-game.json)。

## 部署配置

```dotenv
WEDDING_MAX_INSTANCES=2
WEDDING_DB_CONNECTION_BUDGET=80
BLESSINGS_DB_POOL_SIZE=3
GAME_AI_CONCURRENCY=32
GAME_AI_MAX_INFLIGHT=120
```

每实例两个池和一个 LISTEN 连接，两个实例最多 14 个常态数据库连接。AI 处理名额控制等待外部响应的异步任务数，不是 CPU 线程数。两个实例最多 64 个游戏任务，共享 AI 请求预算仍为 120。提高名额不增加同一轮对话的模型调用次数。

运行时默认每实例 32 个任务；遗留环境变量 `GAME_AI_CONCURRENCY=8` 会覆盖默认值，需改配置并重启。滚动发布的临时额外实例应计入数据库连接预算。平台的实际扩容上限仍由云托管配置决定。

此次没有降低图片或音乐质量，没有缩短预加载等待，也没有变更奖品库存、身份验证或判题安全约束。后台短时负载不接近内存上限，语言迁移的实现和回归成本缺少对应收益。AI 排队、远程响应和静态带宽更值得先处理。

## 范围与复现

本机网络、替身输出长度和数据库性能不同于云环境；这不是 100 位真实 DeepSeek 用户的延迟承诺。短时测试不能证明持续数天无内存泄漏，亦未测试超出 100 人的峰值。生产仍需观察容器内存、CPU 节流、HTTP 延迟、队列等待、AI 429/超时及静态服务命中率。

复现入口为 `tests/container-capacity.mjs --run`，前提是 `BLESSINGS_TEST_DATABASE_URL` 指向 127.0.0.1 的隔离 PostgreSQL，且已构建 `wedding-capacity:current` 镜像。可设置 `CAPACITY_REPLICAS=1/2`、`CAPACITY_OFFLOAD=true/false`、`CAPACITY_WORKERS=8/32`、`CAPACITY_ANSWERS=1/6` 和 `CAPACITY_REPORT` 输出路径。测试启动受限容器，用只读挂载的 `tests/capacity-probe.mjs` 采样；结束时删除测试容器、临时凭据和测试房间数据。诊断日志目录写入命令输出。

压测期间不要并行运行会修改表结构的数据库故障测试。资源仍使用仓库的构建文件；替身服务不读取真实供应商密钥。
